# Bingology — אזור אישי ומעגל חברים

**תאריך:** 2026-11-11
**סטטוס:** טיוטה לבדיקה

## מטרה

היום הדבר האישי היחיד באתר הוא הסימון "כבר ראיתי", והוא נשמר רק בדפדפן שבו סימנו (`site/lib/seen.js`). רוצים אזור אישי ש:

1. **שומר רקורד** — מה ראיתי, מה אני רואה עכשיו ואיפה אני, מה אני רוצה לראות, מה נטשתי, וציון אישי.
2. **עובר בין מכשירים** — טלפון ומחשב רואים אותו דבר.
3. **משותף עם מעגל קטן** — אני ועוד כמה חברים או בני משפחה רואים זה את הציונים והרשימות של זה, ומקבלים הצעה לבינג׳ משותף.
4. **ניתן לשיתוף החוצה** — קישור לקריאה בלבד לפרופיל, למי שלא במעגל.

**הצלחה נראית כך:** אחיה מסמן בטלפון "+1 פרק" ב-Slow Horses, פותח את האתר במחשב ורואה את אותו מצב. דנה, שבמעגל, נותנת 9 ל-The Bear — ואחיה רואה את זה בפיד ובכרטיס הסדרה. בלשונית "שלי" מופיעה סדרה ששניהם רוצים ואף אחד לא ראה.

**קהל:** אני ומעגל קטן (עד ~10 אנשים). לא רשת חברתית פתוחה.

## מחוץ לתחום (כרגע)

- יותר ממעגל אחד למשתמש. המבנה מאפשר להוסיף בהמשך.
- פרופילים ציבוריים שניתן לחפש. יש רק קישור שיתוף ישיר.
- התראות (מייל או push) על פעילות במעגל.
- תגובות או צ׳אט על סדרות.
- התחברות עם סיסמה.
- סטטיסטיקות מעבר לשלושת המונים (ראיתי / רוצה / עכשיו).

## החלטות

| נושא | החלטה | למה |
|---|---|---|
| אחסון והתחברות | **Supabase** (Postgres + Auth), תוכנית חינמית | הנתונים טבלאיים עם קשרים; שאילתות כמו "שנינו רוצים ואף אחד לא ראה" הן SQL פשוט; הרשאות ברמת השורה (RLS) במסד עצמו; האתר נשאר סטטי ב-GitHub Pages |
| כניסה | Google, או קישור קסם למייל | בלי סיסמאות |
| מעגל | אחד למשתמש, מצטרפים בקישור הזמנה | פשוט; שולחים בוואטסאפ |
| ציון | 1–10 שלמים | אותה סקאלה כמו IMDb, שכבר באתר |
| זיהוי סדרה | `tmdbId` | כמו בשאר הקוד |

נשקל ונדחה: Firebase (Firestore מבוסס מסמכים — השאילתות המשותפות מחייבות שכפול נתונים), שמירה כקבצים ב-GitHub (מחייב חשבון GitHub לכל חבר, כל לחיצה היא commit, אין פרטיות).

## ארכיטקטורה

```
GitHub Pages (סטטי, כמו היום)
  site/app.js ── ציבורי: המלצה, רשימה, שחקנים, חיפוש  (לא תלוי ב-Supabase)
       │
       └── נטען רק בלשונית "שלי" / כרטיס סדרה כשמחוברים:
           site/lib/account/*  ──►  Supabase (Auth + Postgres + RLS)
                                         ▲
GitHub Actions (לילי, קיים) ── ping קטן ──┘   מונע השהיה של פרויקט חינמי
```

**עיקרון:** האתר הציבורי לא תלוי בחשבון. ספריית Supabase נטענת דינמית (`import()`) רק כשצריך, כך שמי שלא נכנס לא משלם בזמן טעינה, ותקלה ב-Supabase לא שוברת את ההמלצה.

### שינוי בנתונים הליליים

ל-"+1 פרק" צריך מספר פרקים לכל עונה. `scripts/lib/tmdb.mjs` כבר מושך את פרטי הסדרה מ-TMDB, שכוללים `seasons[].episode_count`. נוסיף שדה `seasonEps: [10, 10, 10, 9]` (בלי עונה 0 / specials) ל-`site/data.json`. אין בקשות נוספות ל-TMDB.

## מודל נתונים

```sql
profiles   (id uuid PK = auth.users.id, name text, circle_id uuid null,
            share_slug text unique null,   -- null = קישור שיתוף כבוי
            created_at timestamptz)

circles    (id uuid PK, invite_code text unique, created_by uuid, created_at)

entries    (user_id uuid, tmdb_id int,                       -- PK (user_id, tmdb_id)
            status text check in ('want','watching','seen','dropped'),
            season int null, episode int null,               -- איפה אני (watching / dropped)
            rating int null check 1..10,
            note text null check length <= 140,
            finished_on date null,
            title text, poster text,                          -- עותק, למקרה שהסדרה יצאה מהמאגר
            updated_at timestamptz)

events     (id bigint PK, user_id, circle_id, tmdb_id, kind text, -- 'started','finished','rated','wanted','dropped'
            rating int null, season int null, created_at)

pick_votes (circle_id, tmdb_id, user_id, vote text check in ('yes','skip'),  -- PK (circle_id, tmdb_id, user_id)
            created_at)
```

- **`events` נכתב רק מטריגר** על `entries` (insert/update), לא מהדפדפן. כך הפיד לא ניתן לזיוף ולא מתפספס. "+1 פרק" לא יוצר אירוע (רעש); מעבר סטטוס ושינוי ציון — כן.
- **`finished_on`** נקבע אוטומטית כשהסטטוס עובר ל-`seen`, וניתן לעריכה.

### הרשאות (RLS)

| טבלה | קריאה | כתיבה |
|---|---|---|
| `profiles` | עצמי + חברי אותו מעגל | עצמי בלבד |
| `entries` | עצמי + חברי אותו מעגל; כל אחד דרך פונקציה `shared_profile(slug)` כשהקישור פעיל | עצמי בלבד |
| `events` | חברי אותו מעגל | אף אחד (רק טריגר) |
| `circles` | חברים בו | יצירה — כל משתמש מחובר; הצטרפות רק דרך פונקציה `join_circle(code)` |
| `pick_votes` | חברי המעגל | עצמי בלבד |

קישור השיתוף עובר דרך פונקציה `security definer` שמחזירה רק `name` + `entries` (כולל `note`, כי הוא חלק מהרקורד שמשתפים). בלי מעגל, בלי אירועים. כיבוי = `share_slug = null`.

## מסכים

המוקאפ שאושר (עיצוב האתר הקיים, מובייל):

1. **לשונית "שלי"** בסרגל הניווט, אחרי "חיפוש".
   - כרטיס פרופיל: אות ראשונה, שם, "במעגל עם …", כפתור **שיתוף** (העתקת קישור / כיבוי).
   - שלושה מונים: ראיתי / רוצה לראות / עכשיו.
   - **רואה עכשיו:** פוסטר, עונה ופרק, "עוד N ערבים" (הפרקים שנשארו לפי `seasonEps`, בקצב של 2 פרקים לערב — אותה ברירת מחדל כמו בהמלצה), פס התקדמות, כפתור **+1 פרק**. בפרק האחרון של הסדרה, "+1 פרק" שואל "סיימת? תן ציון".
   - **רוצה לראות:** פוסטר, מה החברים אמרו ("דנה נתנה 9", "גם יואב רוצה"), ציון בינג׳.
   - **ראיתי:** ממוין לפי ציון (או לפי תאריך), כולל המשפט הקצר. נטשתי מופיע כאן עם "נטשתי בעונה N" ובלי ציון.
2. **המעגל** — באותה לשונית, מתחת.
   - עיגולי אותיות של החברים.
   - **בינג׳ משותף** בעיצוב "כרטיס": שני חברים (אני + מי שהכי הרבה חפיפה ברשימת "רוצה"), סדרה ששניהם רוצים ואף אחד מהם לא ראה, ממוינת לפי ציון בינג׳. כפתורים **יאללה** (מוסיף לשניים "רואה עכשיו" + אירוע) ו**הצעה אחרת** (vote = skip, ממשיך לבאה). אם אין חפיפה — הסדרה עם ציון הבינג׳ הגבוה ביותר שאף אחד במעגל לא ראה.
   - **מה קורה במעגל:** 20 האירועים האחרונים.
   - **הזמנת חבר:** משתף את קישור ההזמנה (Web Share API, ואם אין — העתקה).
   - אין מעגל עדיין: "פתחו מעגל" או "יש לי קישור הזמנה".
3. **כרטיס סדרה (קיים)** — שלוש תוספות כשמחוברים: מה המצב שלי (רוצה / רואה / ראיתי / נטשתי), ציון 1–10, ומה חברי המעגל נתנו. לא מחוברים — הכרטיס כמו היום.
4. **לא מחובר** — בלשונית "שלי": כניסה עם Google / קישור למייל, ושורה שאומרת כמה סימוני "ראיתי" יעברו לחשבון.

הסימון הקיים "כבר ראיתי" ברשימה ממשיך לעבוד כמו היום ללא חשבון. כשמחוברים, הוא קורא וכותב ל-`entries` (status = seen) במקום ל-localStorage.

## זרימות

- **כניסה ראשונה:** אחרי התחברות, אם אין `profiles` — בקשה לשם תצוגה (ברירת מחדל: השם מ-Google). אחר כך `migrate.js` הופך את הסימונים המקומיים לשורות `entries` (רק סדרות שאין להן עדיין שורה), ומסמן ב-localStorage שההעברה בוצעה.
- **קישור הזמנה:** `…/bingology/#join=<code>`. פותחים → אם לא מחוברים, כניסה ואז הצטרפות → מעבר ללשונית "שלי". מי שכבר במעגל אחר מקבל "אתה כבר במעגל עם …. לעבור?".
- **קישור שיתוף:** `…/bingology/#u=<slug>` → תצוגת קריאה בלבד של לשונית "שלי" (בלי מעגל, בלי כפתורים).

## טיפול בשגיאות

- **Supabase לא זמין / ספרייה לא נטענה:** הלשונית "שלי" מציגה "לא הצלחנו להתחבר לחשבון. נסו שוב בעוד רגע" עם כפתור נסיון חוזר. כל שאר האתר עובד.
- **כתיבה נכשלה:** העדכון מוצג מיד (אופטימי). כתיבה שנכשלה נכנסת לתור ב-localStorage ונשלחת שוב באירוע `online` ובטעינה הבאה. אחרי 3 כישלונות — הודעה קטנה "השינוי לא נשמר".
- **התנגשות בין מכשירים:** הכתיבה האחרונה מנצחת (לפי `updated_at`). מספיק למשתמש אחד עם שני מכשירים.
- **סדרה שיצאה מהמאגר:** מוצגת מתוך `title` ו-`poster` השמורים ב-`entries`, בלי ציון בינג׳ ובלי פתיחת כרטיס.
- **קוד הזמנה לא תקין:** "הקישור לא תקין או שפג תוקפו".
- **עזיבת מעגל:** `circle_id = null`; הנתונים נשארים, החברים מפסיקים לראות אותם. מעגל ריק נמחק בטריגר.
- **מניעת השהיה:** `update-data.yml` שולח `select 1` דרך REST בסוף הריצה. כישלון שלו לא מכשיל את העדכון הלילי.

## בדיקות

- **יחידה (`node --test`, כמו היום):** `progress.js` (מעבר עונה, פרק אחרון, `seasonEps` חסר), `jointpick.js` (חפיפה, אין חפיפה, הכל נראה, skip), `migrate.js` (v1, v2, כפילויות, סדרה שלא במאגר), ושדה `seasonEps` ב-`tmdb.mjs`.
- **הרשאות (`tests/rls.test.mjs`):** מול פרויקט Supabase נפרד לבדיקות, עם שלושה משתמשים: שניים במעגל ואחד בחוץ. בודק שמי שמחוץ למעגל לא רואה `entries`/`events`, שאי אפשר לכתוב שורה של אחר או ל-`events`, ושקישור שיתוף כבוי מחזיר כלום. רץ ידנית ובמיזוג, ומדולג כשאין מפתחות.
- **ידנית בדפדפן לפני מיזוג:** כניסה, העברת סימונים, הוספה לרשימה, ציון, "+1 פרק" עד מעבר עונה, הצטרפות בקישור משני דפדפנים, יאללה.

## הקמה (פעם אחת, ידנית)

הוראות ב-README, בסגנון הקיים של TMDB/OMDb:

1. פתיחת חשבון ב-supabase.com ופרויקט חדש (אזור: Frankfurt).
2. הרצת `supabase/schema.sql` ב-SQL Editor.
3. Authentication → Providers: הפעלת Google (Client ID מ-Google Cloud Console) ו-Email. Redirect URL: כתובת ה-GitHub Pages.
4. העתקת Project URL ו-anon key ל-`site/lib/account/config.js` (ציבוריים בכוונה; ההגנה היא RLS).
5. פרויקט שני לבדיקות, ומפתחותיו ב-`.env` (`SUPABASE_TEST_URL`, `SUPABASE_TEST_SERVICE_KEY`).
