# Bingology — נתונים חיים ואתר עצמאי

**תאריך:** 2026-11-09
**סטטוס:** טיוטה לבדיקה

## מטרה

Bingology היום הוא ארטיפקט ב-Claude עם 128 סדרות שהנתונים שלהן כתובים ידנית בקוד. רוצים:

1. **נתונים חיים** לסדרות ששתי הרשימות כוללות (הרשימה האישית — 60, והניו יורק טיימס — 100; יחד 128 סדרות).
2. **שיתוף עם כל אחד** — קישור פתוח שעובד בלי חשבון Claude.

**הצלחה נראית כך:** שולחים קישור לחבר, הוא פותח בטלפון, עובר את השאלון ומקבל המלצה עם פוסטר אמיתי, מספר עונות עדכני וזמינות נכונה בישראל — ואף אחד לא נגע בנתונים ידנית.

## מחוץ לתחום (כרגע)

- עריכת הרשימות מתוך האפליקציה. הרשימות קבועות בקובץ; המבנה יאפשר להוסיף עריכה בעתיד.
- סנכרון "כבר ראיתי" בין מכשירים או משתמשים.
- הרחבה לסדרות שאינן בשתי הרשימות.
- דומיין פרטי (אפשרי בהמשך).
- שינוי הארטיפקט הקיים ב-Claude — הוא נשאר כמו שהוא.

## ארכיטקטורה

```
series.json  (ידני: מי ברשימות + הטעם האישי)
     │
     ▼
scripts/fetch-data  (GitHub Actions, פעם בלילה + הפעלה ידנית)
     │   TMDB  → שנה, עונות, פרקים, אורך פרק, סטטוס שידור, פוסטר,
     │           יוצרים, קאסט + תמונות, זמינות בישראל, תיאור עברי
     │   OMDb  → ציון IMDb
     ▼
site/data.json  (נוצר אוטומטית, נכנס ל-commit)
     │
     ▼
GitHub Pages  →  https://<user>.github.io/bingology
```

שלוש יחידות, כל אחת עם תפקיד אחד:

| יחידה | תפקיד | תלוי ב- |
|---|---|---|
| `series.json` | מקור האמת של מה ברשימות ושל השדות שאי אפשר להשיג ממקור חיצוני | — |
| `scripts/fetch-data` | ממזג את `series.json` עם נתונים חיים, מאמת, וכותב `data.json` | `series.json`, TMDB, OMDb, `data.json` הקודם |
| `site/` | האפליקציה; קוראת רק את `data.json` | `data.json` |

האתר לא יודע ש-TMDB קיים; הסקריפט לא יודע איך האתר נראה. החוזה ביניהם הוא המבנה של `data.json`.

## מבנה הנתונים

### `series.json` — ידני

רשומה לכל סדרה:

| שדה | דוגמה | הערה |
|---|---|---|
| `tmdbId` | `1396` | חובה. נקבע פעם אחת (ראו "חיבור ראשוני") |
| `name` | `"Breaking Bad"` | שם תצוגה; גובר על TMDB |
| `lists` | `["mine","nyt"]` | |
| `nytRank` | `1` | רק אם ב-NYT |
| `genres` | `["crime","thriller","drama"]` | המפתחות הקיימים (`GENRES`) |
| `moods` | `["tense","think"]` | המפתחות הקיימים (`MOODS`) |
| `weight` | `3` | 1–3 |
| `solo` | `false` | "עדיף לבד" |
| `blurb` | `"מורה לכימיה חולה…"` | התיאור העברי שנכתב ידנית; אופציונלי |
| `praise` | `"…"` | "המבקרים בקצרה" (מ-`PRAISE` הקיים); אופציונלי |
| `awards` | `["…"]` | פרסים בעברית (מ-`MORE[i][2]`); אופציונלי |
| `rt` | `96` | ציון Rotten Tomatoes קבוע מהקוד הקיים; `null` אם אין |
| `fallback` | `{year, seasons, episodes, runtime, imdb, lang}` | הערכים מהקוד הקיים; משמשים רק אם אין נתונים חיים ואין נתונים קודמים |

סדר הרשומות בקובץ = הסדר ברשימה האישית (כמו היום).

### `data.json` — נוצר אוטומטית

```json
{
  "updatedAt": "2026-11-10T03:00:00Z",
  "series": [
    {
      "...כל השדות מ-series.json...",
      "year": 2008,
      "seasons": 5,
      "episodes": 62,
      "runtime": 47,
      "status": "ended",           // "ended" | "airing"
      "imdb": 9.5,
      "lang": "en",
      "poster": "https://image.tmdb.org/t/p/w342/…",
      "creators": ["Vince Gilligan"],
      "cast": [{ "name": "Bryan Cranston", "photo": "https://…/w185/…" }],
      "providers": ["netflix"],    // קטגוריות, ראו להלן
      "overviewHe": "…",           // מ-TMDB, משמש רק אם אין blurb
      "fetchedAt": "2026-11-10T03:00:00Z"
    }
  ]
}
```

- `runtime`: חציון של `episode_run_time`; אם ריק — אורך הפרק האחרון ששודר; אם עדיין ריק — הערך מהקוד הקיים.
- `cast`: עד 10 שחקנים, לפי סדר TMDB.
- `lang`: `original_language` מ-TMDB.

## זמינות בישראל

מקור: `watch/providers` של TMDB, אזור `IL`, סוג `flatrate` בלבד (מנוי, לא השכרה/קנייה). הנתונים מגיעים מ-JustWatch.

ספקים ממופים לקטגוריות בקובץ תצורה (`scripts/providers.json`), כדי שאפשר יהיה לתקן מיפוי בלי לגעת בקוד:

| קטגוריה | תווית בשאלון |
|---|---|
| `netflix` | Netflix |
| `hbo` | HBO Max |
| `apple` | Apple TV+ |
| `prime` | Prime Video |
| `disney` | Disney+ |
| `israel` | yes / HOT / סלקום / פרטנר / כאן |
| `other` | אחר |

ספק שלא מופה → `other`, ואזהרה בלוג (כדי לגלות ספקים חדשים).

**שינויים בשאלון ובאפליקציה:**
- סדרה יכולה להיות ביותר מקטגוריה אחת (`providers` הוא מערך). סינון לפי שירותים = יש חיתוך.
- בשאלת השירותים מוצגות רק קטגוריות שיש בהן לפחות סדרה אחת.
- סדרה בלי זמינות בישראל לא נפסלת כשהמשתמש מדלג על השאלה; כשהוא בוחר שירותים — היא לא תופיע. בכרטיס הסדרה יופיע "לא זמינה כרגע בסטרימינג בישראל".
- הקטגוריות הישנות (`paramount`, `amc`, `uk`, `network`) יוצאות.
- תיאור השאלה מתעדכן ל: "לפי הזמינות בישראל, מתעדכן כל יום."

## האתר

הבסיס: הקוד הקיים של הארטיפקט (גרסה `1794236776-b553`), מפוצל ל:

```
site/
  index.html   — שלד, פונטים, נקודת כניסה
  styles.css   — כל ה-CSS הקיים
  app.js       — הלוגיקה הקיימת
  data.json    — נוצר על ידי הסקריפט
```

**נמחק מהקוד:** `RAW`, `META`, `PLAT`, `PCODE`, `NYTR`, `MORE`, `PRAISE`, `P`, `MINE_N` (מחושב מ-`lists`), וכל מנגנון העלאת תמונות השחקנים (`DBH`, `ASSETS`, `window.claude`, `setPhoto`, `bulkPhotos`, `phPanelHTML`, וכו').

**נשאר ללא שינוי בהתנהגות:** השאלון, `rank()` ומשקלותיו, `bL`/`bS`, כרטיס הקולנוע, החלופות, מצב "הפתיעו אותי", לשונית הרשימה, לשונית השחקנים (עכשיו עם תמונות מ-TMDB), מצב כהה, `localStorage` תחת `tvpick:v1`.

**התאמות:**
- הטעינה: מסך טעינה קצר → `fetch("data.json")` → בניית `S` מאותו מבנה שהקוד מצפה לו היום (שכבת המרה אחת, `fromData()`), כדי ששאר הקוד ישתנה מעט ככל האפשר.
- **מזהים יציבים:** היום סדרה מזוהה לפי מיקום במערך, ו"כבר ראיתי" שמור כרשימת מיקומים. עוברים ל-`tmdbId`. בטעינה הראשונה, סימונים ישנים (מספרים 0–127) מומרים לפי הסדר הקיים ב-`series.json`, ונשמרים מחדש תחת `tvpick:v2`.
- **פוסטר:** תמונה מ-TMDB; אם חסרה או נכשלה בטעינה — הגרפיקה הצבעונית הקיימת (`art()`).
- **סדרות דומות:** נשאר `similar()` הקיים (בוחר מתוך 128 הסדרות), רק עם `creators` חיים במקום `MORE`. לא משתמשים ב"דומות" של TMDB — הן מחוץ לרשימות.
- **כרטיס סדרה:** מתווסף "עדיין משודרת" כשהסטטוס `airing`, וזמינות בישראל.
- **כותרת תחתונה:** "הנתונים עודכנו ב-{תאריך}" + קרדיט TMDB ("This product uses the TMDB API but is not endorsed or certified by TMDB") ולוגו, + קרדיט JustWatch לזמינות.

## הסקריפט (`scripts/fetch-data`)

Node.js 20, בלי תלויות חיצוניות (משתמש ב-`fetch` המובנה).

לכל סדרה ב-`series.json`:
1. `GET /tv/{id}?language=he-IL&append_to_response=aggregate_credits,watch/providers,external_ids`
2. אם `name`/`overview` חסרים בעברית — בקשה נוספת ב-`en-US` רק לשדות האלה.
3. `external_ids.imdb_id` → OMDb `?i={imdb_id}` → `imdbRating`.
4. מיזוג עם רשומת `series.json` ⟵ שדות ידניים גוברים.

**קצב:** עד 8 בקשות במקביל ל-TMDB. 128 קריאות ל-OMDb בלילה — בתוך המכסה החינמית (1,000 ביום).

## טיפול בתקלות

**בסקריפט:**
- סדרה שנכשלה (שגיאת רשת, 404, נתון חסר) → נשארים הנתונים שלה מ-`data.json` הקודם, אזהרה בלוג. אם אין לה נתונים קודמים — משתמשים בערכי הבסיס מהקוד הקיים (מוטמעים פעם אחת ב-`series.json` כ-`fallback`).
- OMDb נכשל לסדרה → `imdb` נשאר הערך הקודם.
- **סף כישלון:** אם יותר מ-20% מהסדרות נכשלו, או ש-TMDB לא זמין כלל → הסקריפט יוצא עם שגיאה, `data.json` לא משתנה, ה-workflow נכשל ו-GitHub שולח מייל.
- **אימות לפני כתיבה:** לכל סדרה יש `tmdbId`, `name`, `seasons ≥ 1`, `episodes ≥ 1`, `runtime > 0`, `imdb` בין 0 ל-10; מספר הסדרות שווה למספר ב-`series.json`. כישלון אימות = אותו טיפול כמו סף כישלון.
- commit רק אם `data.json` השתנה בפועל (חוץ מחותמות הזמן).

**באתר:**
- `data.json` לא נטען → הודעה "לא הצלחנו לטעון את הסדרות" + כפתור "נסה שוב".
- תמונה נכשלה → גרפיקה חלופית.
- `localStorage` חסום → האפליקציה עובדת, בלי זיכרון "כבר ראיתי" (כמו היום, עם `try/catch`).

## חיבור ראשוני (חד-פעמי)

`scripts/match-ids` — רץ פעם אחת מקומית:
1. ממיר את המערכים הקיימים מהארטיפקט (`RAW`, `META`, `NYTR`, `MORE`, `PRAISE`) ל-`series.json` בלי `tmdbId`.
2. לכל סדרה: `GET /search/tv?query={name}&first_air_date_year={year}`.
3. התאמה יחידה עם אותה שנה → נכתבת. אחרת (אפס או כמה התאמות) → נרשמת ב-`needs-review.md` עם המועמדים, להחלטה ידנית.

צפי: 5–10 מקרים לבדיקה (למשל The Office US/UK, שטיסל, פאודה, Survivor).

## אירוח ושיתוף

- מאגר **ציבורי** ב-GitHub בשם `bingology`. הקוד והרשימות גלויים; המפתחות לא.
- מפתחות ב-GitHub Secrets: `TMDB_TOKEN` (API Read Access Token), `OMDB_KEY`.
- `.github/workflows/update-data.yml`: רץ כל לילה ב-03:00 UTC, וגם ידנית (`workflow_dispatch`). מריץ בדיקות → `fetch-data` → commit של `site/data.json` אם השתנה.
- `.github/workflows/deploy.yml`: מפרסם את `site/` ל-GitHub Pages בכל push ל-`main`.

**מה המשתמש צריך לעשות (פעם אחת):** ליצור חשבון GitHub, מפתח TMDB ומפתח OMDb (חינם), ולהדביק את המפתחות ב-Secrets. ההוראות המדויקות יופיעו ב-`README.md`.

## בדיקות

- **יחידה** (`node --test`):
  - המרה מתגובת TMDB לרשומת `data.json` (על תגובות שמורות ב-`fixtures/`).
  - חישוב `runtime` במקרי קצה (מערך ריק, ערכים שונים).
  - מיפוי ספקים, כולל ספק לא מוכר → `other`.
  - לוגיקת הגיבוי וסף הכישלון.
  - אימות `data.json`.
  - `rank()`: על נתונים זהים לקוד הקיים, אותן תשובות → אותה רשימה מדורגת (בדיקת רגרסיה מול הארטיפקט).
  - המרת "כבר ראיתי" מ-`v1` ל-`v2`.
- **עשן:** `fetch-data --only 3` מול ה-API האמיתי, רץ ב-workflow לפני הריצה המלאה.
- **ידני בדפדפן:** שאלון מלא עד תוצאה, טלפון (375px) ומחשב, מצב בהיר וכהה, לשונית רשימה, לשונית שחקנים, דף סדרה, וכשל טעינת `data.json`.
